# ADO.NET data sources

SQLite and `ParsingModule` remain ULP's default and most complete workflow. Use the explicit `ulp ado` command when a SQL-capable .NET data source should supply rows directly to the same ULP output formats.

## Supported providers

| Name | Aliases | Use |
| --- | --- | --- |
| `SQLite` | `sqlite3` | A SQLite database without creating `ParsingModule` tables |
| `SqlServer` | `mssql`, `sql-server` | Microsoft SQL Server through the Windows/.NET Framework provider |
| `OleDb` | `ole-db` | An OLE DB provider installed on the current Windows computer |

Run `ulp ado providers` for the machine-readable catalog. SQL Server and OleDb support uses framework facilities already shipped with the application; ULP does not install a database server, an OLE DB driver, or a commercial connector.

## Commands

```powershell
ulp ado providers

ulp ado query `
    --provider SQLite `
    --connection "Data Source=reports.db;Version=3;" `
    --query "SELECT * FROM events WHERE level=@level" `
    --param level=Error `
    --format JSON --output console

ulp ado query `
    --provider SqlServer `
    --connection "Server=.;Database=Logs;Integrated Security=true" `
    --query-file reports\daily-errors.sql `
    --format Excel --output file --output-file daily-errors.xlsx
```

`--query` and `--query-file` are repeatable. ULP's `GO` script splitting, `#name#` constants supplied with `--define name=value`, native command parameters, cancellation, multiple result sets, output fan-out, statistics, and overwrite protection remain available. Constants are preprocessing; values supplied with `--param` are command parameters and are not pasted into SQL text.

```powershell
ulp ado query --provider OleDb --connection "Provider=..." `
    --query "SELECT * FROM [Sheet1$]" `
    --format CSV --output file --output-file sheet.csv `
    --also-output JSON=sheet.json --stats
```

Provider SQL dialects still apply. SQLite-only compatibility functions and `ParsingModule` are available only on the normal SQLite path. OleDb parameters can be positional even when their SQL uses names, so provide repeated `--param` values in command order.

## Connections and secrets

Connection strings may use ULP secret references. Password-like values are masked in normal errors, verbose errors, and logs. Prefer integrated authentication or an environment/secret reference over placing a password directly in shell history.

```powershell
$env:ULP_SQL_CONNECTION = "Server=db;Database=Logs;User ID=ulp;Password=..."
ulp ado --provider SqlServer `
    --connection @env:ULP_SQL_CONNECTION `
    --query "SELECT TOP (20) * FROM dbo.Events"
```

An external server is intentionally not required by ULP's automated tests. Verify the selected driver, authentication, network access, and provider-specific SQL in the deployment environment.
