# Scriban templates and code generation

The `Scriban` output format (alias `Template`) renders query results as arbitrary text. It can print one template, save one rendered file, or generate a directory tree from several templates. This is useful for source code, SQL, configuration, and documentation generation.

## Result model

Templates receive these values:

| Value | Meaning |
| --- | --- |
| `tables` | All result sets |
| `table` | First result set, or null |
| `rows` | Rows from the first result set |
| `columns` | First result set column metadata: `name`, `type`, `ordinal` |
| `row_count` | Row count in the first result set |
| `result_set_count` | Number of result sets |
| `row` / `row_index` | Current row and zero-based index in `each-row` mode |

Each table has `name`, `columns`, `rows`, and `row_count`. Each row exposes its query column names, lowercase names, and snake_case names. For example, `CustomerName` can be read as `row.CustomerName`, `row.customername`, or `row.customer_name`.

## One template

```scriban
# {{ row_count }} errors
{{ for item in rows }}
- {{ item.time_created }}: {{ item.message }}
{{ end }}
```

```powershell
# stdout
ulp --query "SELECT TimeCreated, Message FROM errors" `
    --format Scriban --output console `
    --output.TemplateFile templates\errors.md.scriban

# one output file
ulp --query "SELECT TimeCreated, Message FROM errors" `
    --format Scriban --output file --output-file errors.md `
    --output.TemplateFile templates\errors.md.scriban
```

Exactly one of `InlineTemplate`, `TemplateFile`, `TemplateFiles`, or `TemplateDirectory` is required. `TemplateFiles` is a semicolon-separated list. `TemplateDirectory` uses `*.scriban` by default; set `SearchPattern` and `Recursive` as writer properties when needed.

## Generated output paths

A template can begin with this small front-matter block:

```scriban
---
output: Models/{{ row.name }}.cs
mode: each-row
---
namespace Generated.Models;

public sealed class {{ row.name }}
{
}
```

`output` is a Scriban expression embedded in a relative path. `mode` is either `once` (the default) or `each-row`. In `each-row` mode the body and output path render once for every row in the first result set. This is the convention for generating several files from one template.

When a template declares `output`, when multiple templates are selected, or when a template directory is selected, `--output-file` means the output root directory:

```powershell
ulp --query "SELECT Name AS name FROM schema_tables" `
    --format Scriban --output file --output-file .\generated `
    --output.TemplateDirectory .\templates\codegen
```

Without an `output` directive, a single template and File destination treat `--output-file` as one file. In directory mode, a template such as `Docs\index.md.scriban` defaults to `Docs\index.md`.

ULP rejects rooted paths and paths that resolve outside the selected output root, creates safe subdirectories automatically, and rejects duplicate generated targets. Existing files are replaced only after successful rendering and staging. Add `--no-overwrite` to refuse replacement. Failed or cancelled renders do not publish their staged partial files.

## Multiple templates

```powershell
ulp --query-file schema.sql --format Scriban --output file --output-file generated `
    --output.TemplateFiles "templates\model.cs.scriban;templates\mapping.sql.scriban"

ulp --query-file schema.sql --format Scriban --output file --output-file generated `
    --output.TemplateDirectory templates --output.Recursive ON
```

For an ADO.NET data source, use `--template-file`, `--template-files`, or `--template-dir`:

```powershell
ulp ado --provider SqlServer --connection "Server=.;Database=App;Integrated Security=true" `
    --query-file schema.sql --format Scriban --output file --output-file generated `
    --template-dir templates\codegen --no-overwrite
```

## JSON and YAML data

JSON and YAML still enter through normal ULP virtual tables, so SQL can select, filter, join, and rename the exact fields exposed to a template:

```powershell
ulp --input JSON --from model.json --table model `
    --query "SELECT Name AS name, Namespace AS namespace FROM model" `
    --format Scriban --output file --output-file generated `
    --output.TemplateDirectory templates\models

ulp --input YAML --from services.yaml --table services `
    --query "SELECT Name AS name, Port AS port FROM services" `
    --format Scriban --output file --output-file generated `
    --output.TemplateFile templates\service.config.scriban
```

Templates receive plain query data rather than unrestricted application objects. Parse and render failures name the source template. Use `--output.StrictVariables OFF` only when intentionally tolerating missing fields. The bundled example is under `samples\templates\codegen`.
