# Universal Log Parser MCP server

Start the stdio server with:

```powershell
ulp --mcp
ulp --mcp --database agent-session.sqlite
ulp --mcp --queries-dir C:\Data\ulp-queries
```

The server uses one shared SQLite connection. It supports multiple provider types simultaneously and exposes these tools:

- `ListDataProviders`: discover provider keys.
- `GetRecordProviderHelp`: obtain generated provider/property help.
- `CreateVirtualTable`: create or replace a ParsingModule virtual table; omitted names identify their provider, such as `tEvt1` or `tCsv1`.
- `ListTables`: inspect the shared SQLite catalog.
- `DescribeTable`: inspect columns before composing SQL.
- `ExecuteQuery`: execute SQLite and return all result sets as JSON with metadata.
- `ListSavedQueries`: discover recursive Query-library recipes, stable IDs, commands, descriptions, source properties, output defaults, and declared parameters.
- `GetSavedQuery`: inspect one recipe's full metadata and authoritative SQL by ID, command, or unique title; connection-string secrets are masked in the response.
- `LoadSavedQuery`: validate overrides and return the complete ParsingModule + query SQL and native SQLite bindings without executing it.
- `ExecuteSavedQuery`: repeat validation, create the declared source when needed, bind parameters natively, and return JSON results.
- `ListResultWriters` and `GetResultWriterHelp`: discover reusable export formats and properties.
- `ExportQuery`: render a query as JSON, XML, CSV, TSV, Markdown, HTML, YAML, SQL, Excel, or another Common writer; return it inline or save it to an explicit path.
- `MaterializeTable`: copy a streaming ParsingModule table into a TEMP table before joins or window queries.
- `DropTable`: remove a session table.
- `ClearQueryHistory`: clear session history without changing data.
- `ShowQueries`: review the session query history.

For a reliable agent workflow: first look for a reusable recipe with `ListSavedQueries`. Inspect it with `GetSavedQuery`, call `LoadSavedQuery` with overrides, review `preparedSql` and `bindings`, and only then call `ExecuteSavedQuery` with the same arguments. For an ad-hoc workflow, discover a provider, read its help, create one or more virtual tables, list and describe the tables, then execute bounded queries with `LIMIT`. Materialize streaming sources before plans that rescan them. A file-backed `--database` keeps materialized SQLite tables between server runs; ParsingModule virtual tables should be recreated for each new process.

## Saved Query library

The MCP server reads the same external, recursive `.sql` library as the CLI. Its location is selected in this order: `--queries-dir`, `ULP_QUERIES_DIR`, then `queries` beside `ulp.exe`. The server validates the complete library before returning results, including duplicate command aliases and malformed metadata. Relative IDs such as `Files/dir.sql` remain stable when the installation directory changes.

Example tool sequence:

```text
ListSavedQueries(search: "directory")
GetSavedQuery(query: "dir")
LoadSavedQuery(query: "dir", parametersJson: "{\"extension\":\".log\"}", source: "C:\Logs\*")
ExecuteSavedQuery(query: "dir", parametersJson: "{\"extension\":\".log\"}", source: "C:\Logs\*")
```

`parametersJson` accepts only parameters declared by `-- parameter: NAME=DEFAULT` metadata. Values are converted to SQLite text, integer, real, or null values and bound through `SQLiteParameter`; they are never pasted into SQL. Provider aliases are normalized and unknown providers, parameters, invalid table identifiers, or structured parameter values are rejected during load. Recipe `default-format` and `default-destination` remain visible as metadata, but MCP execution deliberately returns JSON.

The MCP transport is local stdio and intentionally exposes SQL, input sources, saved recipes, and explicit export paths. Query-library tools never accept an arbitrary library path: the server administrator chooses the root at startup. `ListSavedQueries`, `GetSavedQuery`, and `LoadSavedQuery` do not execute SQL; `ExecuteSavedQuery` can read the recipe's sources and run its SQL. Treat library files as trusted code, connect only trusted MCP clients, and grant the ULP process only the filesystem and event-log access that workflow requires. Connection-string secrets and secret-like parameter names are masked in tool responses, and saved-query history is sanitized.

## Client configuration

Use the absolute path to `ulp.exe`. The process must stay on stdio; do not wrap it in a command that writes banners or diagnostics to standard output.

### VS Code / GitHub Copilot

Create `.vscode/mcp.json` in the workspace (or the equivalent user-level MCP configuration):

```json
{
  "servers": {
    "ulp": {
      "type": "stdio",
      "command": "C:\\Tools\\ULP\\ulp.exe",
      "args": ["--mcp", "--database", "C:\\Data\\agent.sqlite"],
      "env": {
        "ULP_CONFIG_DIR": "C:\\Tools\\ULP\\config",
        "ULP_QUERIES_DIR": "C:\\Data\\ulp-queries"
      }
    }
  }
}
```

### Claude Desktop

Open `%APPDATA%\Claude\claude_desktop_config.json` on Windows (Settings > Developer can open the local-server configuration), add this server under `mcpServers`, then fully quit and restart Claude Desktop:

```json
{
  "mcpServers": {
    "ulp": {
      "command": "C:\\Tools\\ULP\\ulp.exe",
      "args": ["--mcp"],
      "env": { "ULP_CONFIG_DIR": "C:\\Tools\\ULP\\config" }
    }
  }
}
```

### Cursor

Create `.cursor/mcp.json` in the workspace or use Cursor's MCP settings. Cursor uses the `mcpServers` top-level key:

```json
{
  "mcpServers": {
    "ulp": {
      "command": "C:\\Tools\\ULP\\ulp.exe",
      "args": ["--mcp"],
      "env": { "ULP_CONFIG_DIR": "C:\\Tools\\ULP\\config" }
    }
  }
}
```

Cline and other stdio-capable clients use the same executable, argument, and environment values; add them through the client's MCP server settings and follow that client's required top-level JSON shape.

## Verification and troubleshooting

Run `ulp --version` and `ulp --list-providers` first to verify the executable and dependencies. In the MCP client, call `ListSavedQueries` and `ListDataProviders`, then `ListTables`. If saved-query discovery fails, verify the configured library directory and fix any duplicate command reported with both file paths. If startup fails, use an absolute executable path, verify that the working account can read sources and Windows Event Logs, inspect the client's MCP logs, and run `ulp --mcp` in a terminal to see sanitized startup errors. MCP is a long-running stdio process, so an apparently idle terminal is normal. Do not write anything except MCP protocol messages to standard output.

`ExecuteQuery` continues to return JSON because JSON is the most interoperable MCP payload. TOON 4.1 is available through `ExportQuery` and the CLI for token-sensitive, uniform tabular data, but it remains a working-draft ecosystem format and is not the MCP default.
