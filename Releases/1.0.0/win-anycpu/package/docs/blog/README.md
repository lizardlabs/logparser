## Writing an Article

1. Copy [TEMPLATE.md](TEMPLATE.md) to a descriptive lowercase hyphenated filename.
2. Replace every owner-review placeholder.
3. Use tested ULP commands or clearly label conceptual examples.
4. Use fictional/non-sensitive data.
5. Link to authoritative manual chapters for reference details.
6. Check claims about versions, packages, security, licensing, and external products.
7. Run documentation link/anchor checks.
8. Obtain author/editor approval before adding it to Published Articles.

## Editorial Rules

- Prefer a useful narrative/problem/solution over copying reference documentation.
- Include publication/update dates and real author attribution; never fabricate either.
- Identify the tested ULP version.
- Label experimental features.
- Avoid secrets, customer data, private paths, and unsupported performance claims.
- Respect third-party trademarks/copyright and source quotation limits.
- Keep evergreen corrections in the manual; update the article when historical context matters.
