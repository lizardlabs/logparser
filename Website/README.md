# ULP documentation website

This independent ASP.NET Core website renders the authoritative ULP Markdown manual on the server. It is intentionally small: Razor Pages, Markdig, one navigation file, one stylesheet, and a little progressive-enhancement JavaScript.

## Run locally

Requirements: the .NET 10 SDK. .NET 10 is the current long-term-support runtime and avoids starting a new deployment on the near-end-of-support .NET 8 line.

```powershell
cd .\Website
dotnet restore
dotnet run
```

Open the URL shown by ASP.NET Core. The project links `../Documentation/UserGuide/**/*.md` into `Content` in build and publish output, so documentation remains maintained in one place.

Run the smoke test:

```powershell
.\Test-Site.ps1 -Configuration Release
```

The same checks can validate an already published folder:

```powershell
.\Test-Site.ps1 -PublishedDirectory .\artifacts\framework-dependent
```

## Maintain the site

- Edit user documentation under `../Documentation/UserGuide`.
- Edit sidebar groups, titles, descriptions, and order in `navigation.json`.
- Edit site/footer URLs and hosting behavior in `appsettings.json` or environment variables.
- Edit the layout in `Pages/Shared/_Layout.cshtml` and visual design in `wwwroot/css/site.css`.
- Do not copy Markdown into the website folder manually; the project includes it automatically.

Internal Markdown links are rewritten to clean `/docs/...` routes. Raw HTML in Markdown is disabled. Relative assets are served only from the manual content root through an extension allowlist.

## SEO configuration

Before public deployment, set the final canonical origin. For example:

```json
{
  "Site": {
    "CanonicalBaseUrl": "https://docs.example.com",
    "RequireHttps": true
  }
}
```

The site emits page titles, descriptions, canonical links, Open Graph and Twitter metadata, `robots.txt`, and a generated sitemap. When `CanonicalBaseUrl` is empty, it uses the current forwarded request scheme and host.

Environment variables use ASP.NET Core's double-underscore syntax:

```text
Site__CanonicalBaseUrl=https://docs.example.com
Site__RequireHttps=true
Site__IdeasUrl=https://github.com/lizardlabs/logparser/issues/new
```

Configure the hosting proxy to forward the original scheme and host. The application accepts standard `X-Forwarded-For` and `X-Forwarded-Proto` headers.
Set `Site__TrustForwardedHeaders=true` only when the application is behind a trusted reverse proxy that removes client-supplied forwarded headers and writes its own. IIS integration normally supplies the request scheme without this option.

## Publish for shared hosting

Framework-dependent Windows deployment:

```powershell
.\Publish.ps1
```

This creates `artifacts/framework-dependent`, `framework-dependent.zip`, and a matching
SHA256 checksum. Development symbols are omitted from the deployment package.

Self-contained Windows deployment, which does not require the hosting account to have the matching .NET runtime installed:

```powershell
.\Publish.ps1 -Runtime win-x64 -SelfContained
```

This creates `artifacts/win-x64-self-contained`, a ZIP archive, and its SHA256 checksum.
Use `-SkipArchive` only when the unpacked folder is sufficient.

Linux x64 deployment:

```powershell
.\Publish.ps1 -Runtime linux-x64 -SelfContained
```

Upload the **complete generated folder** from `artifacts`. Do not upload only the DLL. Markdown content, static assets, configuration, dependencies, and the IIS `web.config` generated by the Web SDK must remain together.

For IIS shared hosting:

1. Use a hosting account that supports ASP.NET Core applications.
2. For a framework-dependent deployment, ensure the host has the ASP.NET Core 10 Hosting Bundle or compatible runtime. Otherwise use the self-contained package.
3. Point the site/application directory at the uploaded publish folder.
4. Use an application pool configured for **No Managed Code** when the host exposes that setting.
5. Bind the domain and HTTPS certificate at the hosting control panel or reverse proxy.
6. Set `Site__CanonicalBaseUrl` to the final HTTPS origin.
7. Request `/`, `/docs/getting-started`, `/robots.txt`, and `/sitemap.xml` after deployment.

For an upgrade, publish to a new local folder, back up the current hosted folder, then replace all deployed files as one version. Preserve hosting-specific environment variables outside the uploaded package where possible.

## Security defaults

The site renders only trusted local Markdown, disables Markdown HTML, confines document paths, and sends CSP, anti-framing, MIME-sniffing, referrer, and browser-permission headers. Production configuration enables HTTPS redirection; HTTPS termination itself is normally configured by the hosting provider.

The site has no database, login, cookies, telemetry, Markdown editor, or upload endpoint. Public deployment should remain read-only.
