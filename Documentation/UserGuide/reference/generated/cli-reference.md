## Lightweight text analysis

`ulp analyze` streams ordinary text without opening SQLite. It reports line and character counts, known file bytes, unknown byte counts for sources such as standard input, maximum and truncated line lengths, bounded repeated-line counts, and keyword-based severity counts.

```powershell
ulp analyze .\logs --include "*.log"
ulp analyze build.log --format json --top 20
type build.log | ulp analyze --stdin --normalize-lines log-template
```

The default `--parser auto` still uses the bounded text analyzer. It labels each source with an observed content shape such as `log-like`, `json-like`, or `plain-text`, together with confidence and evidence. These labels are heuristics, not claims that structured fields were parsed. Use `--parser text` to disable content-shape inference.

`--normalize-lines log-template` replaces common timestamps, GUIDs, hexadecimal values, and numbers only for repeated-line grouping. Original line counts and severity classification still use the source text. The default is `none`.

Input without a byte-order mark is decoded as UTF-8. UTF-8, UTF-16, and UTF-32 byte-order marks are recognized. Any decoder replacements are counted in `decoding_replacement_characters`; they are never silently described as clean decoding. Standard-input byte counts are reported as unknown because character-oriented console input cannot provide the original encoded byte length.

The operation is bounded by `--max-line-length`, `--max-distinct-lines`, `--max-top-line-length`, and `--top`. JSON output explicitly reports line truncation and when the distinct-line tracking limit was reached. `--require-content` returns exit code 4 when no lines were analyzed.

## Multiple data providers

Every `--input` starts a new source block. Its `--from`, `--table`, `--input-config`, and `--input-options` belong to that block. All blocks are created as `ParsingModule` virtual tables in one SQLite connection, so providers can be mixed and joined.

```powershell
ulp --input EVT --table events --from System `
    --input CSV --table lookup --from C:\data\lookup.csv `
    --query "SELECT e.*, l.owner FROM events e LEFT JOIN lookup l ON e.EventID=l.id LIMIT 100"
```

Omitted table names identify their provider, for example `tEvt1`, `tText1`, and `tCsv1`; numbering is independent per provider and advances past collisions. With no explicit query, ULP runs one automatic query per table. `--select`, `--where`, `--group-by`, `--having`, `--order-by`, and `--limit` customize those queries.

Automatic-query options let you build a simple SELECT without writing the complete SQL statement:

```powershell
ulp --input EVT --table logs --from System `
    --query.Select "TimeCreated, EventTypeName, SourceName, Message" `
    --query.FilterLevel "Warning, Error" --query.FilterDate Last24Hours `
    --query.OrderBy "TimeCreated DESC" --query.Limit 200
```

## Lazy file lists, exclusions, and archives

Stream-based providers expand comma- or semicolon-separated `--from` file paths and globs lazily. ULP opens the first match without first walking the complete recursive tree, so a SQL `LIMIT` can stop work early. Quote a source containing a literal comma or semicolon.

Prefix a glob with `!` to exclude matching files from all positive sources. When the list contains only exclusions, `*` in the current working directory is the implicit positive source. Prefix a literal filename beginning with `!` as `!!name`. Examples:

Filename-only exclusions apply at every recursive depth. A relative path exclusion is resolved from each positive wildcard's directory; for example, `C:\logs\*.txt;!archive\*.txt` omits `C:\logs\archive`.

```powershell
ulp -i TextLine --from 'C:\logs\*;!*.txt' --input.Recurse -1 --query 'SELECT * FROM tText1 LIMIT 100'
ulp -i TextLine --from '!*.bak;!*.tmp' --input.Recurse -1 --query 'SELECT * FROM tText1 LIMIT 100'
```

Use `archive-path|entry-glob` to stream every matching non-directory archive entry. The outer archive path can itself be a glob. ZIP, TAR, RAR, 7z, BZip2, and the other installed archive formats are supported; ordinary `.gz` remains a transparent single stream.

```powershell
ulp -i TextLine --from 'C:\logs\*.zip|*.log' --query 'SELECT * FROM tText1 LIMIT 100'
ulp -i TextLine --from 'file:///C:/logs/secure.zip?password-env=ULP_ARCHIVE_PASSWORD|*.log' --query 'SELECT * FROM tText1'
```

For encrypted archives, `password-env` names an environment variable; its value is never placed in the source string, stream name, or normal diagnostics. Do not place passwords directly in source URLs.

## Ordered SQL and query files

`--query` and `--query-file` may be repeated and execute in their command-line order on the same connection. Query-file wildcards are expanded in case-insensitive lexical order.

```powershell
ulp --query-file "sql\01-*.sql" --query "INSERT INTO work VALUES (3)" `
    --query-file "sql\02-*.sql" --query "SELECT * FROM work"
```

Use `--connection-scope query` to reopen the configured database between top-level actions. ULP recreates configured virtual tables after each reopen. This isolates queries but prevents in-memory tables created by one action from being used by the next.

## SQLite connection

The default is an in-memory database; `--memory` makes that choice explicit. Use `--temp-db` for an ordinary temporary SQLite file that is deleted after ULP closes it. Use `--database results.sqlite` or `--db results.sqlite` for a persistent file, or `--connection` for a complete connection string. These modes are mutually exclusive.

Database mode and path are omitted from normal output. `--verbose` reports them on standard error, and `--stats` adds `database_mode` and `database_path` to the JSON execution summary. Connection-string secrets continue to be masked. SQL can materialize virtual-table results with `CREATE TABLE ... AS SELECT ...` or `INSERT INTO ... SELECT ...`.

## Automation contract

Standard output contains result data only. Concise errors, `--verbose` diagnostics, and the single-line JSON emitted by `--stats` go to standard error. Exit codes are stable: 0 success, 1 unexpected failure, 2 usage/configuration, 3 SQL/provider execution, 4 unmet result condition, 5 output failure, and 6 post-action failure.

`--require-rows`, `--expect-scalar`, and `--condition-query ... --require-condition` turn query results into batch gates. `--output none` consumes results without rendering them. `--no-output-if-empty` stages textual output and leaves an existing target untouched when no rows are returned.

Post-actions use `--after` plus repeated `--after-arg` values. `--after-when` can be `success`, `rows`, `empty`, `file`, or `condition`. ULP starts the executable directly without an implicit shell and exports `ULP_ROWS`, `ULP_RESULT_SETS`, `ULP_FIRST_VALUE`, `ULP_OUTPUT_FILE`, and `ULP_CONDITION` to it.

## Interactive operation

Run `ulp` without an action to see concise CLI help, `ulp --menu` for the guided interactive menu, or `ulp --shell` to enter the SQL shell directly. Set `--startup-mode menu` (or save that choice under Options) to restore menu-on-empty-command behavior; `--no-menu` overrides it for one invocation. SQL executes after a trailing `;` or when `.r`, `.run`, `run`, or `go` is entered. `.show` displays the buffer, `.c`/`.clear` clears it, `.h`/`.help` lists commands, and `.menu` returns to the existing main menu without nesting menus. `.q`, `.quit`, `.exit`, `quit`, and `exit` leave the shell cleanly. Press **Ctrl+C** to cancel a running query.

The default Beginner menu provides guided sources and tables, output selection, the Query library, Query Builder, the Text User Interface (TUI), Options, and Help. Use `--advanced-menu` or **Options > Change runtime settings** to show the SQL shell, SQLite connection options, background jobs, and multiple-output management. **Choose a query** includes **Preview table data (20 rows)** and can open a table in the TUI query editor. Query Builder offers JOIN, UNION, materialization, filtering, grouping, sorting, and paging. **Use this query** provides the shared preview, edit, copy, execute, and Create View actions.

Long Markdown help, information tables, and Terminal query results use the shared pager when the terminal is interactive. Auto mode pages only content taller than the terminal. Space/PageDown/Down advances, PageUp/Up goes back, Home/End jumps, **A** shows all remaining content in terminal scrollback, and Q/Escape returns. After showing all remaining content, press P to resume paging or Enter/Q/Escape to return. Use `--pager=always`, `--pager=never`, or `--no-pager`; redirected input/output never waits for pager keys.

Menus use arrow-key navigation and type-to-filter search. SQL Shell aliases remain direct commands.

In the TUI table viewer, use **File → Open Query**, **Save Query**, or **Save Query As** for `.sql` files. Choose **File → Edit Query**, edit the multiline SQL, and select **Run**. The tables menu is refreshed with the new results, and query errors remain in the editor dialog.
