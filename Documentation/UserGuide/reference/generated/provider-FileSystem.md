# Files and directories with paths, sizes, timestamps, and optional media metadata: -i=FileSystem

## Description

Files and directories with paths, sizes, timestamps, and optional media metadata. Command line switch to use this input format is -i=FileSystem.

**Category:** File system
**Aliases:** `FS`

## Data Provider

Depending on the provider, the source used with `FileSystem` can be:
- One or more local paths, optionally containing glob wildcards.
- An HTTP, FTP, or S3 URL when remote input is supported.
- A provider-specific name or value, such as a Windows Event Log channel.

For stream-based providers, comma/semicolon-separated file sources are expanded lazily. Prefix exclusions with `!` (`C:\logs\*;!*.txt`); an exclusion-only list implies `*`, and `!!name` escapes a literal leading exclamation mark. Use `archive.zip|*.log` to stream matching archive entries. Encrypted archives can read a password from an environment variable with `file:///C:/logs.zip?password-env=ULP_ARCHIVE_PASSWORD|*.log`.

## Optional media metadata

File enumeration is lazy. File paths, sizes and timestamps do not read file contents. `Metadata` is JSON and is read only when requested, then cached for that row. Supported images, audio and video supply relevant `directories`, each containing `name`, `tags` (`id`, `name`, typed `value`, `description`) and optional `errors`. Unsupported or disabled metadata returns `{}`. `IgnoreErrors` returns read failures as `Metadata.error`; disable it to stop on failures. Use `json_each` to explore tags and `json_extract` to retrieve values. Opaque binary tags expose byte length rather than their full payload.
