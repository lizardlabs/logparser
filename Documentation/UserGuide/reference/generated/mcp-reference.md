# Universal Log Parser MCP server

Start the stdio server with:

```powershell
ulp --mcp
ulp --mcp --database agent-session.sqlite
ulp --mcp --queries-dir C:\Data\ulp-queries
```

The server supports multiple provider types and independent task sessions. Existing clients can omit `sessionId` to use the default database selected by `--database`. New named sessions use separate in-memory databases.

## Independent task sessions and CLI discovery

MCP initialization instructions identify the actual CLI executable and installed skills directory. Read the direct `ulp://runtime` resource first. It contains the CLI, application, working, Query-library, and skills paths plus the packaged skill names and their `ulp://skills/{name}` resource URIs. Clients without resource browsing can call `GetRuntimeInfo`, `ListAgentSkills`, and `GetAgentSkill` for the same discovery. Do not guess an installation or skills path. In a release package CLI discovery identifies the root launcher, not just the application in `runtime`.

Read the task-appropriate skill before planning a query. The data-investigation skill requires provider help, `DescribeTable`, a bounded preview, and SQL derived only from returned columns. The code-intelligence skill explains live versus materialized SourceCode analysis. Resource reads are restricted to packaged `SKILL.md` files; arbitrary paths and traversal are rejected.

```text
CreateSession(sessionId: "code-review")
CreateVirtualTable(recordProviderType: "SourceCode", recordProvider: "C:\Repo\*.cs", name: "code", sessionId: "code-review")
DescribeTable(tbl: "code", sessionId: "code-review")
ExecuteQuery(query: "SELECT Kind, Name, SourcePath, StartLine FROM code LIMIT 20", sessionId: "code-review")
CloseSession(sessionId: "code-review")
```

Pass the same `sessionId` on **every** data operation: create/describe/list tables, execute/export/saved-query execution, materialize/drop, and query history. Library discovery and help are shared and need no session ID. `ListSessions` returns active IDs without waiting for their queries. IDs are case-sensitive; unknown IDs fail instead of silently creating a new database. Existing IDs cannot be reset by creating them again.

Up to 32 named sessions can exist. Each keeps its own tables, history (latest 1,000 statements), and operation lock. A second operation on a busy session returns a helpful error after five seconds; other sessions remain usable. This wait limit does **not** impose a query execution time limit. Keep queries bounded and avoid concurrent operations on the same session. Closing a named session discards its data; the default session closes with the server.

Sessions isolate SQLite state, **not permissions or users**. Every client has the server account's filesystem privileges. A separate CLI process cannot see an MCP in-memory database or its TEMP tables. To reuse materialized data across processes, explicitly write it to a file-backed SQLite database and finish the write before reading it from another process. Never put secrets into a session ID.

## Available tools

- `GetRuntimeInfo`: discover the CLI, Query library, installed skills, and skill resource URIs without exposing connection strings or secrets.
- `ListAgentSkills` and `GetAgentSkill`: discover and read the packaged ULP workflows when a client does not display MCP resources.
- `CreateSession`, `ListSessions`, `CloseSession`: manage independent task databases.

- `ListDataProviders`: discover provider keys.
- `GetRecordProviderHelp`: obtain generated provider/property help.
- `CreateVirtualTable`: create or replace a ParsingModule virtual table; omitted names identify their provider, such as `tEvt1` or `tCsv1`.
- `ListTables`: inspect the selected session's SQLite catalog.
- `DescribeTable`: inspect columns before composing SQL.
- `ExecuteQuery`: execute SQLite and return all result sets as JSON with metadata.
- `ListSavedQueries`: discover recursive Query-library recipes, stable IDs, commands, descriptions, source properties, output defaults, and declared parameters.
- `GetSavedQuery`: inspect one recipe's full metadata and authoritative SQL by ID, command, or unique title; connection-string secrets are masked in the response.
- `LoadSavedQuery`: validate overrides and return the complete ParsingModule + query SQL and native SQLite bindings without executing it.
- `ExecuteSavedQuery`: repeat validation, create the declared source when needed, bind parameters natively, and return JSON results.
- `ListResultWriters` and `GetResultWriterHelp`: discover reusable export formats and properties.
- `ExportQuery`: render a query as JSON, XML, CSV, TSV, Markdown, HTML, YAML, SQL, Excel, or another supported writer; return it inline or save it to an explicit path.
- `MaterializeTable`: copy a streaming ParsingModule table into a TEMP table before joins or window queries.
- `DropTable`: remove a session table.
- `ClearQueryHistory`: clear session history without changing data.
- `ShowQueries`: review the session query history.

For a reliable agent workflow: first look for a reusable recipe with `ListSavedQueries`. Inspect it with `GetSavedQuery`, call `LoadSavedQuery` with overrides, review `preparedSql` and `bindings`, and only then call `ExecuteSavedQuery` with the same arguments. For an ad-hoc workflow, discover a provider, read its help, create one or more virtual tables, list and describe the tables, then execute bounded queries with `LIMIT`. Materialize streaming sources before plans that rescan them. A file-backed `--database` keeps materialized SQLite tables between server runs; ParsingModule virtual tables should be recreated for each new process.

## Saved Query library

The MCP server reads the same external, recursive `.sql` library as the CLI. Its location is selected in this order: `--queries-dir`, `ULP_QUERIES_DIR`, then `queries` beside `ulp.exe`. The server validates the complete library before returning results, including duplicate command aliases and malformed metadata. Relative IDs such as `Files/dir.sql` remain stable when the installation directory changes.

Example tool sequence:

```text
ListSavedQueries(search: "directory")
GetSavedQuery(query: "dir")
LoadSavedQuery(query: "dir", parametersJson: "{\"extension\":\".log\"}", source: "C:\Logs\*")
ExecuteSavedQuery(query: "dir", parametersJson: "{\"extension\":\".log\"}", source: "C:\Logs\*")
```

`parametersJson` accepts only parameters declared by `-- parameter: NAME=DEFAULT` metadata. Values are converted to SQLite text, integer, real, or null values and bound through `SQLiteParameter`; they are never pasted into SQL. Provider aliases are normalized and unknown providers, parameters, invalid table identifiers, or structured parameter values are rejected during load. Recipe `default-format` and `default-destination` remain visible as metadata, but MCP execution deliberately returns JSON.

The MCP transport is local stdio and intentionally exposes SQL, input sources, saved recipes, and explicit export paths. Query-library tools never accept an arbitrary library path: the server administrator chooses the root at startup. `ListSavedQueries`, `GetSavedQuery`, and `LoadSavedQuery` do not execute SQL; `ExecuteSavedQuery` can read the recipe's sources and run its SQL. Treat library files as trusted code, connect only trusted MCP clients, and grant the ULP process only the filesystem and event-log access that workflow requires. Connection-string secrets and secret-like parameter names are masked in tool responses, and saved-query history is sanitized.

## Client configuration

Use the absolute path to `ulp.exe`. The process must stay on stdio; do not wrap it in a command that writes banners or diagnostics to standard output.

### Codex and the ChatGPT desktop app

Codex, its IDE extension, and the ChatGPT desktop app share MCP configuration for the same Codex host. Add ULP from the command line:

```powershell
codex mcp add ulp `
  --env ULP_CONFIG_DIR=C:\Tools\ULP\config `
  --env ULP_QUERIES_DIR=C:\Data\ulp-queries `
  -- C:\Tools\ULP\ulp.exe --mcp --database C:\Data\agent.sqlite
codex mcp list
```

Or add it to `~/.codex/config.toml` (or a trusted project's `.codex/config.toml`):

```toml
[mcp_servers.ulp]
command = 'C:\Tools\ULP\ulp.exe'
args = ['--mcp', '--database', 'C:\Data\agent.sqlite']
env = { ULP_CONFIG_DIR = 'C:\Tools\ULP\config', ULP_QUERIES_DIR = 'C:\Data\ulp-queries' }
startup_timeout_sec = 20
tool_timeout_sec = 120
```

In the desktop app or IDE extension, open **Settings > MCP servers**, add the same STDIO command, save, and restart the server/extension. Use `/mcp` to confirm that ULP is connected.

### VS Code / GitHub Copilot

Create `.vscode/mcp.json` in the workspace (or use **MCP: Add Server** / **MCP: Open User Configuration**):

```json
{
  "servers": {
    "ulp": {
      "type": "stdio",
      "command": "C:\\Tools\\ULP\\ulp.exe",
      "args": ["--mcp", "--database", "C:\\Data\\agent.sqlite"],
      "env": {
        "ULP_CONFIG_DIR": "C:\\Tools\\ULP\\config",
        "ULP_QUERIES_DIR": "C:\\Data\\ulp-queries"
      }
    }
  }
}
```

For a configuration shared with GitHub Copilot CLI and Agent Host, current VS Code guidance recommends a workspace `.mcp.json` or user `~/.copilot/mcp-config.json`; those portable files use an `mcpServers` object. Confirm the location against the installed client version.

### GitHub Copilot CLI

Add ULP interactively with `/mcp add`, or persist a local STDIO server from a terminal:

```powershell
copilot mcp add ulp -- C:\Tools\ULP\ulp.exe --mcp --database C:\Data\agent.sqlite
copilot mcp list
```

Use `~/.copilot/mcp-config.json` for user-wide configuration or a repository `.mcp.json` for project configuration. Add environment variables in the JSON form when ULP needs custom config or Query library directories.

## First agent prompts

Start with an inspection-only request so you can see which ULP tools the client intends to call:

```text
Use the ULP MCP server. List saved queries related to files, inspect the `dir`
recipe, then load it with extension=.log and source=C:\Logs\*. Do not execute it;
show me the prepared SQL and parameter bindings for review.
```

After reviewing the plan, request execution explicitly:

```text
Execute the prepared ULP `dir` recipe with the same arguments. Summarize the
largest ten files and keep the original paths and byte counts in the answer.
```

For an unfamiliar source, ask the agent to discover before it queries:

```text
Use ULP to discover the CSV provider and its properties, create tables for
employees.csv and departments.csv, describe both schemas, materialize them if
the join requires rescanning, and propose a bounded join query. Wait for my
approval before executing or exporting anything.
```

## Verification and troubleshooting

Run `ulp --version` and `ulp --list-providers` first to verify the executable and dependencies. In the MCP client, call `ListSavedQueries` and `ListDataProviders`, then `ListTables`. If saved-query discovery fails, verify the configured library directory and fix any duplicate command reported with both file paths. If startup fails, use an absolute executable path, verify that the working account can read sources and Windows Event Logs, inspect the client's MCP logs, and run `ulp --mcp` in a terminal to see sanitized startup errors. MCP is a long-running stdio process, so an apparently idle terminal is normal. Do not write anything except MCP protocol messages to standard output.

`ExecuteQuery` continues to return JSON because JSON is the most interoperable MCP payload. TOON 4.1 is available through `ExportQuery` and the CLI for token-sensitive, uniform tabular data, but it remains a working-draft ecosystem format and is not the MCP default.
