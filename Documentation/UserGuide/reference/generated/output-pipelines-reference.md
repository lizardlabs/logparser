# Output Formats and Destinations

ULP models ordinary output as a pipeline:

```text
Query result -> Format -> Destination
```

**Format** controls representation: TextTable, TextList, PlainText, CSV, TSV, JSON, XML, Markdown, TOON, HTML, YAML, SQLScript, Excel, and the other registered formats. Common short aliases such as TXT and TXTLIST are also accepted. Format properties own delimiters, headers, quoting, indentation, null representation, and similar encoding choices.

**Destination** controls where results go: Terminal, File, Text User Interface, or None. Terminal is the first and default interactive choice and uses formatted tables on standard output; the CLI spelling remains `--output console`. None executes the query and records statistics without displaying data. None and Text User Interface do not ask for irrelevant format or file settings.

Use the Text User Interface (TUI) for interactive browsing. Excel is available for File output. Markdown, MarkdownChart, and TOON may use more memory for large results; prefer a streaming format such as CSV or JSON for very large exports.

Excel emits a deliberately small standards-compliant `.xlsx` package. Every SQLite result set becomes a separate worksheet, worksheet IDs and cell references are valid SpreadsheetML, numbers use invariant formatting, and no optional style/shared-string parts are required. This keeps the workbook portable across Microsoft Excel, LibreOffice, and web spreadsheet viewers.

HTML defaults to Tailwind styling. Use `--output.StyleMode BuiltIn` for a small offline stylesheet, `Custom` with `--output.CustomStyles <css>` for only your CSS, or `Clean` for semantic HTML with no CSS and no classes. Multiple SQLite result sets are emitted as sections in one valid HTML document.

One query can write the same result to several file formats. The query runs once, and every selected file receives the same result sets.

## CLI

```powershell
ulp --query "SELECT * FROM events" --output file --format CSV --output-file events.csv
ulp --query "SELECT COUNT(*) FROM events" --output none --stats
ulp --query "SELECT * FROM events" --output file --format CSV --output-file events.csv `
    --also-pipeline JSON=events.json
```

`--output` and `--destination` select where results go. `--format` selects how results are encoded. Use `--also-pipeline FORMAT=FILE` for each additional file.

Output filenames accept date/time tokens such as `{yyyy-MM-dd}`, the aliases `{date}` and `{datetime}`, and `{n}`. The `{n}` token selects the first available positive integer and never replaces an existing target.

## Post-build output gallery

Local builds run `Tests\Build-OutputGallery.ps1` after `ulp.exe` is ready. The script executes controlled TextLine and recursive FileSystem reports, a three-result workbook/document example, plus a bounded System/Application EVT report, then fans each result out once to every compatible file writer. It creates the latest gallery under `bin\<Configuration>\output-gallery`, with `manifest.json` and `README.md` indexes for manual review.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tests\Build-OutputGallery.ps1 -Configuration Release

# Fast/CI build without the manual gallery:
dotnet build .\UniversalLogParser.csproj -p:RunOutputGallery=false
```

The gallery covers TextTable, TextList, PlainText, JSON, TOON, XML, CSV, TSV, Markdown, HTML, YAML, SQLScript, MarkdownChart, and Excel. Its validation checks worksheet counts, positive worksheet IDs, unique A1 cell references, and the expected Office ZIP parts for Excel. TXT and TXTLIST are documented short names. Terminal/Console, TUI, and None are destinations rather than reviewable file formats. Use `-SkipEventLog` where EVT is unavailable and `-Strict` when any skipped or missing output must fail. Normal post-build mode records unavailable Windows Event Log access as a visible skip without failing otherwise valid TextLine/FileSystem output.
