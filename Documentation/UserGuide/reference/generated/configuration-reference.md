# Configuration files

ULP uses editable Log Parser-style configuration files. Lines beginning with `#` are comments.

## Precedence

Configuration is applied in this order:

1. Built-in defaults.
2. `defaults.input.<TYPE>.config` or `defaults.output.<TYPE>.config` from `--config-dir` (the `config` subdirectory of the working directory by default).
3. An explicit `--input-config` or `--output-config`.
4. `--input-options` or `--output-options` from the command line.

Configuration filenames distinguish object types: use names such as `defaults.input.EVT.config` and `defaults.output.JSON.config`.

Input/output configuration files are already scoped by their filename, so their properties remain unprefixed. Provider defaults are loaded automatically; generated `CREATE VIRTUAL TABLE` SQL therefore stays portable and does not contain a config-file path.

Application configs and CLI arguments can use explicit namespaces:

```text
--input CSV --from data.csv --input.DelimiterOptions.DelimiterCharacter ","
--output console --format JSON --output.IndentJson ON --output.IncludeMetadata ON
--query.Select "date, status, COUNT(*) AS requests"
--query.GroupBy "date, status" --query.OrderBy "requests DESC"
```

ULP strips the `input.`, `output.`, or `query.` namespace before applying the selected settings. Nested settings use dotted property paths.

Short aliases are equivalent: `--i.ReverseDirection`, `--i.EVT.ReverseDirection`, `--o.IndentJson`, `--w.IndentJson`, and writer-qualified forms such as `--w.JSON.IndentJson` are accepted alongside the canonical names.

Application options are loaded first from `defaults.ulp.config`, then from every `--config` file, and finally from the command line. The last scalar value wins. Source blocks and queries are additive.

## Session SQL and Query library

ULP does not create implicit built-in virtual tables. Optional, reviewable examples under `session-sql` define event-log, current-file, calendar, and number tables through the normal lifecycle mechanism. Their supplied provider-aware names are `tEvt1`/`tEvt2`, `tFile1`, `tDate1`, and `tNumber1`. Load only the sources needed by a session, for example `--session-init-file session-sql\numbers.sql --query "SELECT * FROM tNumber1 LIMIT 10"`. Loading the same supplied file again safely recreates its temporary table instead of adding a duplicate; an empty initialization creates nothing. This uses the same explicit behavior in batch, menu, shell, TUI, web, and MCP hosts.

The top-level **QUERY · Query library** browser reads `*.sql` files recursively from the installed `queries` directory. Its folder browser shows compact Query, Command, and Description columns. Set `--queries-dir <directory>`, `ULP_QUERIES_DIR`, or the persistent interactive setting to use another library. A query can declare metadata in its leading comments:

```sql
-- title: Recent errors
-- description: Show the newest Windows error events.
-- command: errors
-- provider: EVT
-- source: System
-- table: events
-- input-options: -Direction:BACKWARD
-- default-format: Terminal
-- default-destination: console
-- parameter: minimum_level=2
SELECT 1;
```

Run tagged queries with `ulp -c.errors` or `ulp --command errors`. Recipe parameters are native SQLite named parameters: use `--param minimum_level=3`, `--param.minimum_level 3`, or `--p.minimum_level 3`. An explicit source or output option overrides recipe metadata. Exact `-c <file>` remains the application-config shorthand.

Set `ULP_GROK_PATTERNS_DIR` or `--grok-patterns-dir` to replace the installed Grok/RegEx catalog. An explicit catalog is validated before a RegEx provider is created.

## Generate complete editable files

```powershell
ulp --generate-input-config EVT
ulp --generate-input-config CSV --config-output config\csv-production.config
ulp --generate-output-config JSON
ulp --generate-app-config config\job.config
```

Generated input and output files include every writable property, including nested properties such as `DelimiterOptions.DelimiterCharacter`. They can be edited manually.

## Automatic defaults

If `defaults.input.EVT.config` exists, ULP automatically applies it to every EVT block unless that block supplies `--input-config`. The path is not included in generated `CREATE VIRTUAL TABLE` SQL. Likewise, `defaults.output.JSON.config` is used automatically for the JSON writer.

```powershell
ulp --config-dir config --input EVT --from System --input-options="-Direction:BACKWARD"
```

Here the command-line property overrides the corresponding value loaded from the file. Use the `--option=value` form when the value itself begins with `-`.

Pass `--use-factory-defaults` (aliases: `--factory-defaults`, `--no-provider-config`) to disable automatic input-provider config discovery and use the provider's built-in factory defaults. An explicit `--input-config` is still honored and its properties are embedded without exposing the filename.

## Environment variables and secrets

Environment configuration is loaded after application config files and before command-line arguments. CLI values therefore have final precedence. Hierarchical properties use double underscores:

```powershell
$env:ULP_OUTPUT = "JSON"
$env:ULP_OUTPUT_FILE = "result.json"
$env:ULP_OUTPUT__IndentJson = "OFF"
$env:ULP_INPUT__Direction = "BACKWARD"
$env:ULP_QUERY__FilterDate = "Last24Hours"
$env:ULP_ARGS = '--require-rows --stats'
```

`ULP_INPUT__*` supplies defaults to every input block. `ULP_OUTPUT__*` and `ULP_QUERY__*` map to writer and Common query-builder properties. Use `--no-env` for a hermetic invocation.

Sensitive values can remain outside configs by using an explicit reference as the entire property value:

- `@env:NAME` reads one environment variable.
- `@file:path` reads a mounted secret file and removes final line endings.
- `@wincred:target` reads a Generic credential from Windows Credential Manager for the current logon session.

References are resolved only in memory and are not printed by ULP. Environment variables are convenient for CI/CD but are generally plaintext to the process; prefer a mounted secret or OS/vault integration for stronger production isolation.

## Interactive settings

The Options menu can save, reload, reset, and display effective settings. Non-sensitive preferences are stored as command-line-style entries in `<config-dir>/settings.config` and load automatically; a missing file simply uses built-in defaults. Saved values include no-command startup behavior (Help or Menu), Beginner/Advanced menu mode, terminal paging mode, diagnostic toggles, table display, default Format/Destination pipelines, the maximum concurrent background jobs, and non-secret AI endpoint/model settings.

```text
--stats
--beginner-menu
--startup-mode="Help"
--pager="Auto"
--destination="console"
--format="Markdown"
--max-background-jobs="2"
```

ULP intentionally does **not** write API keys, custom AI headers, SQL parameter values, or connection strings to `settings.config`. Supply secrets through `@env:`, `@file:`, or `@wincred:` references. Effective-settings screens and errors mask sensitive values. Base64 is not encryption and is not used as secret storage.

## SQL lifecycle hooks

Lifecycle SQL is useful for connection-local setup such as initial virtual tables, temporary tables, indexes, and audit rows. The ordering is deterministic:

1. **Session initialization** runs once after a SQLite connection opens and before ULP creates its configured source tables.
2. **Before query** runs immediately before each user query.
3. **After query** runs only after that user query and all output writers complete successfully.
4. **Session cleanup** runs once before the connection closes.

Use `--session-init-sql` / `--session-init-file`, `--before-query-sql` / `--before-query-file`, `--after-query-sql` / `--after-query-file`, and `--session-cleanup-sql` / `--session-cleanup-file`. Options are repeatable and retain command-line/configuration order. Named values supplied with `--param` are bound in hooks as SQLite parameters. Hook commands run outside the per-query hook pipeline, so they cannot recurse. A failing hook fails the affected query/session; cleanup is still followed by deterministic connection disposal. Query-scoped and background connections receive the same initialization, per-query, and cleanup ordering.

```text
--session-init-sql="CREATE VIRTUAL TABLE startup_events USING ParsingModule('System','-i:EVT');"
--before-query-sql="INSERT INTO audit(phase) VALUES('before');"
--after-query-sql="INSERT INTO audit(phase) VALUES('after');"
```

## SQL parameters and output patterns

Use repeatable `--param NAME=VALUE` options with SQLite placeholders `@NAME`, `:NAME`, or `$NAME`. ULP binds values safely; it does not perform SQL string replacement.

Output filenames may contain .NET date/time format tokens, for example `orders-{yyyy-MM-dd}.csv` or `orders-{yyyy-MM-dd-HHmmss}.csv`. The aliases `{date}` and `{datetime}` expand to those two common forms. `{n}` selects the first available positive integer without overwriting a file. Background outputs additionally support `{JobId}`. Use `--also-pipeline FORMAT=FILE` repeatedly to send one query result to multiple non-interactive files.

## File logging

Use `--log` for `logs\ulp-{date}.log`, or `--log-file <path>` to choose a date-token filename. `--log-max-size-mb` defaults to 10 and `--log-retain-days` defaults to 14. Logs include lifecycle, SQL, timing, warning, and sanitized error details. `--silent --verbose` keeps the console silent while retaining detailed file diagnostics.

AI Chat is experimental and opt-in. Use `--help-ai` for configuration, secret references, privacy, and review-before-execution guidance.
